# Manual steps and in-game verification

## 0. Build where the NeoForge mavens are reachable

The build sandbox used to write this code blocked `maven.neoforged.net`, Mojang's servers, `maven.parchmentmc.org` and `dl.cloudsmith.io`. The NeoForge module has therefore **not been compiled here**. What *was* verified:

- The Gradle configuration loads: MDG 2.0.148 resolves and the `runClient`, `runServer` and `runGameTestServer` tasks exist.
- Every SmartBrainLib call used (class names, packages, `ExtendedBehaviour` hooks, `SmartBrainOwner`, `BrainActivityGroup`, `BrainUtils`, sensor and behaviour generics) was checked against SmartBrainLib's `1.21` branch source.
- Every NeoForge call used (`EntityJoinLevelEvent.loadedFromDisk`, `CropGrowEvent.Post`, `PistonEvent.Post`, `ServerTickEvent.Post`, `ModConfigSpec`, `GameTestHolder`, `PrefixGameTestTemplate`) was checked against NeoForge's `1.21.1` branch source.
- SmartBrainLib's own `gradle.properties` pins NeoForge `21.1.191`, Parchment `2024.11.17` and version `1.16.11`, matching `gradle.properties` here.
- The sources pass `javac` with no syntax errors. The only errors are the missing Minecraft types themselves.

**Not verified:** vanilla Minecraft method signatures, which have no reachable source. If `./gradlew build` reports errors, these are the likeliest spots:

## 1. Optional assets

Built-in blueprints exist for everything, so these are optional.

- **`hut.nbt`**: build a hut within a 5×5 footprint in a dev world (`./gradlew runClient`).
  1. Place a structure block one below the floor at the north-west corner.
  2. Set Save mode, name `emerald:hut`, relative position `0 1 0`, size `5 4 5`, entities off. Press Save.
  3. Copy `runs/client/saves/<world>/generated/emerald/structures/hut.nbt` to `minecraft-neoforge/src/main/resources/data/emerald/structure/hut.nbt`.
- **`chicken_collector.nbt`**: the same process for collector Mk I. Its origin is the hopper (the pen floor's centre), with the chest one below.
- **`gametest_platform.nbt`**: generated by `tools/make_gametest_platform.py`, an original plain stone platform used only by GameTests.

## 3. In-game verification script

Run as op in a dev world. Lower `emerald-server.toml` → `simulation.eggWasteWindowTicks` to speed up M6.

1. **M1:** `/emerald spawn`, then `/emerald inspect`. Save and quit, reload, then `/emerald inspect` again: same UUIDs, roles and values.
2. **M2:** bodies wander, and `/emerald plan` shows scores and routines. A zombie at night: civilians flee and the guard attacks it.
3. **M3:** place a chest and run `/emerald warehouse <pos>`. Plant and bonemeal wheat near the centre. The farmer harvests, replants and deposits.
4. **M4:** put 32 planks in the chest and run `/emerald request planks`. The general delivers 16 to the builder.
5. **M5/M10:** stock about 120 planks and some bread. The director opens HOMELESS and builds huts on flat free ground by itself (`/emerald ledger` shows `PROJECT_STARTED`). Once beds exceed adults and food is at twice the reserve, newcomers arrive.
6. **M6:** fence a pen and run `/emerald pen <air from> <air to>` with chickens inside. After the waste window, `/emerald problems` shows EGGS_WASTED. Put a hopper in the chest: the researcher requests it, the general brings it, and the researcher digs the floor and places it.
   - An egg over it gives PASS: `/emerald knowledge`, `/emerald design`.
   - Eggs that all miss it give FAIL: TESTED_FALSE and a failed revision.
7. **M7:** with a book in the chest, the researcher writes the result (`/emerald library`), teaches the child (OBSERVED), and the child later reads the book (TESTED_TRUE via DOCUMENT). The builder installs collector Mk I.
   - If eggs are still wasted in a wider pen, a full-floor collector prototype is built, trialled and then adopted (`/emerald design`).
   - Kill the researcher: designs and books remain.
8. **M9:** walk more than 128 blocks away for a day. `/emerald offline` shows catch-up events and pending results. On return, wheat and eggs are reconciled into the chests and queued blocks are placed.
9. **M8 (optional):** run `ollama run qwen3` and set `ai.enabled = true`. `/emerald ledger` shows `AI_REQUESTED` and then `AI_PROPOSAL_ACCEPTED` or `AI_PROPOSAL_REJECTED`; with Ollama stopped, the table keeps the loop going.
